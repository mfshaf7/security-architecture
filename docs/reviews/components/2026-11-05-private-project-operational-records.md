# Private project operational records and scoped source access

## Summary

Review the operator-approved extension of existing registration and source
workflows to installation-private operational records and private GitHub source.
This approves the source design and local conformance, plus controlled local
activation only for the exact merged sources selected by the existing composed
Security decision. Real-account operating acceptance remains pending.

Workspace Governance retains policy; WGCF stores canonical current records,
immutable revisions and original receipts in its existing database. OOS owns
operator requests, identity, recovery and exact next actions. Platform owns
source credentials, managed checkout and lifecycle binding. Console projects
those authorities. Project source stays in its selected Git repository.
No new service, database, records Git repository, installer, account grant,
ART initiative or independent approval authority is introduced. Gary authors
source; the delegated accountable human reviews and merges. The main agent
retains Security judgment; this is not an independent assessment.

## Scope Delta

New public and private physical source-only repository registrations use the
installation's private operational storage. Existing Git records and pending
source reviews retain their original authority. Products, shared components,
whole-system state migration and private Prototype application import are
outside this first source-only route. Internal registration grants no shared
control-plane, runtime, publication or automatic model authority.

### Registration and recovery

The database stores current record, immutable revisions, original full command
and original receipt. One transaction covers policy, compare-and-swap, actor
binding, positive/negative outcome, provider uniqueness and replay. A retry reads
the original outcome before refreshing dependencies. It never rewrites history
or reinterprets a changed request as the original operator decision. Process-death
and concurrent acceptance tests exercise the store. Missing/corrupt canonical
state and database outages fail closed; they do not become empty registers.

OOS private request provenance precedes canonical effects. A derived locator
can be rebuilt only from the complete original record. The original accepted
request, expected record version, current provider identity, exact decision,
operator attribution and policy digest remain bound through Intake and Inventory.
Restore references the actual last suspension/retirement receipt. Native receipts
retain their actual namespace and version, without fabricated Git merges or
public registry revisions. Registration metadata cannot replace its envelope.

Private or unverified project metadata is denied before public source writers
publish it. New native records do not modify public Workspace Governance or
Studio source. Existing product/component decisions retain their actual Git
contracts; a private listing outage does not replace their authority.

### Reads and source authority

Metadata pages/search/counts and selected status lookups are bounded and
installation-scoped. Selected status resolves at most 25 exact names through
one indexed joined query, without history fanout. Absence is only a successful
authenticated response for the exact selection; an unrecognized route, timeout
or unavailable database is not absence. Repo Control and Registry preserve
current internal registration and actual provider identity. Overlap between
native and legacy identity is denied, not silently resolved by precedence.

The live Delivery picker searches bounded current Registry pages, with explicit
partial results and no static example fallback. Selected linking uses exact
current registration independently of the visible search page. Changing search
does not grant admission or replace server readiness; failed reads disable the
choice and source submission. Private choices remain operator-visible internal
metadata, not automatic model context or public Studio records.

The Platform source reader is a distinct existing-authorizer role with only
`read-instance-source-authority`. It cannot list/export records, read history,
accept decisions or reconcile. Installation and endpoint come from private
accepted configuration. OOS retains its original authenticated service role for
writes. Source proofs bind current canonical owner alias, immutable provider ID,
record version and accepted policy bytes. Ordinary source requires active
Inventory; proposed/admitted Intake remains limited to setup. A physical GitHub
basename is never inferred as the canonical alias. Native admission loss,
namespace change or policy mismatch cannot fall back to public source.

Delivery repository readiness independently reevaluates this current ordinary
source admission and binds the actual installation, version, record digest and
accepted source-authority policy in the existing durable receipt. A stale or
foreign reference cannot produce ready evidence. Fresh linking reevaluates
eligibility, so suspension or unavailable native authority blocks it. No public
per-project rule, fabricated Git revision or new application test gate is
required. The existing Catalog reference remains unchanged; this consumer does
not migrate Catalog operational storage or qualify private Studio import.

### Private source custody and host effects

The existing Source App's full accepted identity, installation and permissions
are verified before reducing a temporary token to Metadata/Contents read for
exactly one repository. The Metadata App remains unchanged. Finite control
inspection verifies provider identity, main commit/tree, regular paths, blob
hashes, UTF-8 and size, then rechecks current source and registration. Neither
that read nor checkout invokes a model or accepts an application.

Authenticated Git reads allow only clone, fetch and exact branch-reference
inspection. Platform derives the fixed GitHub URL and installation-private
managed checkout. The request cannot select a destination, arbitrary command,
provider URL or token. Native canonical source and worktrees remain within the
existing managed source area, under a derived installation namespace; private
names are not added to public root owner indexes. Legacy source keeps its
original path. Hooks, submodule recursion, global configuration, ambient
credentials and HTTP redirects are excluded from this read transport.

Git reads have a complete bounded deadline. A nonblocking per-owner file lock
prevents an uncertain original read from overlapping its retry. The temporary
askpass credential is private volatile state under the existing provider
PrivateTmp, removed before return. Source read tokens are revoked on success
and handled failures; uncertain revocation withholds completion. An abrupt
process kill cannot guarantee finally-block execution: existing provider expiry
bounds any residual token, and volatile custody does not survive PC restart.
No token, private key, command body or source file enters generic journals.

OOS retains pre-effect checkout provenance, resumes only its exact selected
source, and preserves dirty, branched, linked or unique work. Existing owner
controls use non-source checkout with truthful revoked-read-token evidence;
they do not require a dummy commit or source-write session. Setup still applies
only the reviewed finite control plan, validates trusted control data without
executing arbitrary project scripts, publishes as Gary, requires exact-head
human review/merge, and retires only its own temporary resources. Ordinary
source rechecks current native admission before push. Explicit future model
use still requires the existing purpose/profile/context and operator boundaries.

### Installation lifecycle

The existing accepted complete-runtime lifecycle prepares one private original
installation ID and distinct source-reader secret before derived connection
files. Restart retains them. Missing original identity with retained derived
bindings blocks recovery; it never silently creates a replacement installation.
The original installation state belongs in protected runtime backup/recovery.
The lifecycle verifies WGCF migration ancestry before enabling native roles
or writes; later proven descendant revisions remain compatible.

The source host reuses the existing authenticated OOS-to-Platform private CNI
connection. Only that explicitly commissioned host connection admits RFC1918
HTTP. Public, link-local and credential-bearing destinations remain denied.
The connection is loaded from a fixed private JSON file beside accepted record
custody, not runtime shell text or browser fields. Provider credentials do not
enter argv. New services are not exposed and no per-project App setup is added.

## Review Areas

- Identity: exact operator/caller, installation, repository and Gary/human split.
- Secrets: distinct source-only reader, full-App verification, reduced read
  tokens, volatile credential custody, revocation and no ambient fallback.
- Delivery: exact original input, canonical receipts, CAS/replay, source scope,
  human review, migration dependency and source cleanup ownership.
- Runtime: private durable records, bounded reads/Git effects, crash recovery,
  managed paths, existing lifecycle and explicit inactive defaults.
- AI: no automatic private context export; explicit approved model/context
  custody remains required for any later authoring request.

## Decision

conditional on the exact merged-source composed decision. This is not evidence
of a completed runtime activation or real-account operating acceptance.**

The candidate evidence includes atomic/process-death storage tests, native
Intake/Inventory policy and source role denial tests, real isolated Source App
HTTP permission/revocation checks, real local Git checkout and recovery,
Gary commit/publish, delegated exact-head review, squash merge and owned cleanup,

service commissioning or end-to-end real Console operating witness is claimed.

The canonical installation policy selects the internal route, while absent or
disabled backend/transport configuration remains denied. Selection alone cannot
replace the pending exact Security decision, source match and migration checks.
Native service flags and private connections are commissioned only by that
accepted lifecycle; no direct environment edit or alternate policy is accepted.
