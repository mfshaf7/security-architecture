# Console purpose-profile lifecycle and exact policy source continuation

## Summary

Assess the operator-approved maintenance extension across Governance Operations
Console, Operator Orchestration Service and Platform Engineering. Reuse native
profile intents, private request state, the existing Platform operation store,
Gary maintenance publication, human source review, native receipts and the
admitted runtime runner. No service, database, generic shell, AI decision maker
or independent source authority is added.

This supersedes the same batch's
[request-usability source assessment](2026-11-06-model-profile-request-usability.md)
for this additional boundary and inherits its unchanged Proposal, account,
private-project, context and provider controls. The main agent retains Security
and final landing judgment; Gary authors implementation and the standing
delegated accountable human reviews/merges. This is a source assessment, not an
independent review or a live activation decision.

## Scope And Authority

OOS owns exact request/revision identity, real review artifacts, explicit role
binding, native transitions and coordination receipts. Platform owns full policy
preparation, source publication/application, runtime reconciliation and rollback.
Console supplies choices and progress, never policy JSON, endpoints, actor IDs,
shell commands, credentials, worktrees or final AI decisions. Security acceptance
for activation/exception is separate from ordinary operator request approval.

The workflow defaults off in the adapters. The operator-approved publication
selects preparation/lifecycle in canonical Platform policy; activation still needs
exact paired-source and composition acceptance. Commissioned preparation uses the accepted CGG origin; a supporting
context reference is not permission to send future restricted data to a model.
The declared input classification remains proposed scope.

## Implemented Controls

- Preparation reads clean accepted Platform main and derives existing caller,
  output, environment, source and full target policy. It validates the native
  three-document candidate. No model invocation or gateway-health prerequisite
  is used. Reading unchanged amendment setup cannot submit or suspend a profile.
  The Console loads actual operating rules rather than treating register-summary
  omissions as empty policy. Before/after values remain in the private review.
- Browser changes are bounded operating rules and existing runtime limits.
  Create/amend produce suspended policy; integration contracts, provider routes
  and privileges are not arbitrary form input. Request wording is metadata.
- Approve/reject plus reason is saved atomically as a real immutable artifact
  with the native revision-bound transition. Its digest addresses actual stored
  bytes and its request-scoped logical URI maps to the owned decision-read API.
  External native references remain compatible, but automated implementation
  requires a real saved owner decision. No fake reference or hash is generated
  in the browser.
- Security acceptance is an additional explicit action by an admitted bound
  operator, with a real reason and exact source/candidate binding. Revision
  invalidates it. Ordinary approval cannot substitute for that acceptance, and
  advisors cannot perform either final decision.
- The distinct Platform fulfiller may read only approved handoffs and their
  stored decisions. It cannot list all requests, read unapproved requests,
  issue operator review commands or impersonate an operator. Private state,
  accepted origins, bounded responses and no credential redirects preserve
  custody. Provider secrets and original private project data are not copied
  into source controls, browser recovery or receipts.
- One original operation is bound to each real request. A shared policy writer
  boundary prevents concurrent source requests from producing incompatible
  receipt chains. Native apply writes only the three policy documents. Gary
  uses the existing narrow source identity and maintenance publication bridge;
  ambient human credentials are never used to publish implementation.
- Source review checks the exact Gary author, repository, base and head. The
  authenticated accountable human explicitly approves/merges after checks;
  exact-head matching and merged readback precede source fulfillment. A rejected
  or interrupted source preparation can be explicitly declined: retain its
  patch privately, record genuine failure evidence and retire only proven owned
  branches. Earlier/manual implementation is shown as retained evidence rather
  than silently starting another operation.
- Native receipt/readback proves applied source; running permission is separate.
  The existing runner receives the commissioned management overlay, image,
  private journal and credential references. It does not reinstall a provider
  or replace the managed gateway with its unmanaged baseline. New profiles retain stable base-capability task identities; their source
  compatibility enters management only through receipted source admission.
  Source hashes, observed policy state and active-provider readiness are checked
  before a verified outcome. Failure remains unverified.
- A private accepted management overlay can keep the control plane online with
  every profile inactive. The gateway still denies inference for inactive or
  retired profiles. The unmanaged/no-overlay launch guard remains unchanged.
- Rollback consumes the original native receipt/bundle, denies later source
  drift, creates another reviewed Gary change and checks exact restored bytes.
  Running state remains separate. Source cleanup preserves changed/unique work
  rather than deleting unknown state. Original operation identity and progress
  survive an interrupted acknowledgement or process restart.

## Capability permission-profile extension

The operator explicitly chose several permission presets per installed AI
capability with manual selection. The stable base profile retains its task,
caller, input and output authority. Variants identify that base and retain their
own lifecycle, reviewed scope notes and limits. Actual runtime resolution checks
contract compatibility and inherited base caller identity. Variants add no caller
registration or grant; caller IDs remain globally unique. Native candidate
validation invokes that resolver before source publication. Base-contract/source-
binding updates keep related variants coherent without granting new activation;
prior variant acceptance and limits remain separate. Source projection and runtime
eligibility both deny effective use under an inactive base.

The bounded `profile.assign` action shares existing authenticated intent,
revision/history, receipt, retry and reconciliation controls. It accepts no new
caller, task schema, URL, credential, instruction or executable path. Both base
and selected policy must allow the invocation; numeric ceilings are intersected.
Free-text scope notes document reviewed policy and do not become an access filter.
OOS/CGG retain context authority. Managed adapters retain conservative no-retry and
shared provider concurrency limits. Dedicated-account output uses a byte bound;
unsupported native token controls are not represented as enforced token limits.

The gateway captures one configuration snapshot for policy and model selection.
Original invocation identity stays stable through profile changes; saved results
and uncertain in-flight requests cannot invoke a second provider. Optional
`policy_profile_id` records the actual restriction preset while preserving the
base capability/task contract and legacy configuration behavior.

Policy revision reuses the original request and exact revision. It refreshes the
source/candidate and supporting context before a native revise transition, clears
prior acceptance and requires resubmission/review. The original command recovers
a recorded revision without repeated preparation or context admission. Direct
metadata edits cannot silently remove prepared policy. The UI distinguishes
behavior/input/output/instructions, actual operating settings and review wording.
An unprepared maintainer request is not shown as an implemented AI capability.

This is the same source-only maintenance boundary and adds no control plane,
provider credentials, independent policy engine or AI final decisions. New
profile names and operating rules are source-published; the UI discloses that.
Private request notes and context remain in operational custody. Exact composed
Security acceptance and a real disposable operating witness remain mandatory
before enabling the staged lifecycle/preparation extension.

## Exact Source Admission

The earlier whole-tree check would invalidate the provider when its own reviewed
profile policy changed. Extend that existing admission for policy data only.
The accepted executable tree remains the anchor. An unbroken native receipt and
merged-readback chain must reproduce exact Git bytes through only the registry,
access-plane and runtime-assist policy documents. Saved approval, candidate,
activation/exception acceptance, receipt and readback digests must agree.
Unrelated source, unreviewed policy, missing/corrupt evidence, dirty source or a
broken chain fails closed. Ordinary composed acceptance can advance the anchor
after the same proof. This is not a generic descendant or GitHub-main bypass.

These checks consume existing private owner state. No new signing authority,
policy engine, database or orchestration layer is introduced. They do not claim
protection from a malicious host administrator who already owns these stores
and the runtime; that host trust boundary is inherited unchanged.

## Publication And Data Boundary

The current native workflow versions operating rules in the registered Platform
source repository. The Console must disclose that source review publishes those
rules and profile names. Scope notes describe permitted data and must not contain secrets or actual
private project content. Request reasons, context, decisions, source credentials,
raw account data, receipts and rollback bundles stay in private operational
storage. Source publication is not a grant to export private project files or
send them automatically to an AI provider. Product packaging and replacement
of the existing source-backed configuration remain separate work.

## Evidence And Limits

Controlled tests exercise real native source apply, validation, merged readback,
profile creation/task configuration and receipt rollback in disposable Git
repositories. They cover decline, interrupted authoring, original-operation
recovery, writer exclusion, stale source/operation, unreviewed code rejection,
all-inactive management-only launch and an unavailable runtime. GitHub identity,
review/CI and Kubernetes responses are controlled test inputs; these are not
claims of real provider entitlement or operating acceptance.

OOS tests cover atomic/durable decision replay, separate Security roles,
candidate/source binding, invalidation, approved-only fulfiller reads, native
all-intent submission and no-change admission rejection. Console tests and
browser walkthroughs cover explicit decisions without raw references, policy
loading, bounded history, typed evidence, before/after review, original recovery,
source/runtime separation and readable layouts at both review sizes. Existing
native schema/source-lock compatibility, API route parity, owner structure,
composition and source guards remain required.

The original five native schemas are unchanged. Isolated source/browser proof
cannot close the live qualification requirement. After operator preview review
and source landing, commission the exact accepted composition, renew the normal
Console session if stale, and exercise a disposable profile through the actual
Console including negative/interruption paths while preserving working profiles.
Do not report current live independence or activation from these source tests.

## Decision

Approved for the described source delta. The operator reviewed preview and
authorized publication; canonical Platform policy now selects preparation and
lifecycle with the existing accepted origins and explicit Security operator list.
This selection does not establish operating acceptance. Exact source landing,
current owner-record index, composed Security acceptance and the real disposable-
profile operating witness remain separate release conditions.
