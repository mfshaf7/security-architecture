## Scope Delta

### Accounts and credentials

Platform verifies native App ID, installation ID, immutable account ID, login,
personal/organization type, exact purpose permissions, events, suspension and
token lifetime. The optional protected connection selection contains identifiers
and deliberate grants, never tokens or private keys. Optional key slots remain
under each existing purpose's Vault prefix and cannot select arbitrary paths.
One installation may use the same approved App across accounts or separately
commissioned purpose-compatible Apps. A customer's setup must not depend on
the developer's App identifiers or keys.

Metadata requires an explicitly approved account-wide read grant for future
repositories. Creating credentials preserve their native installation selection;
selected installations are not widened. Source authoring keeps its separately
verified Source App. Lifecycle grants remain limited to exactly one named,
immutable-ID-verified repository and retain the existing activation gate.
Connecting an account does not grant account-wide lifecycle write access.

The existing timer renews separate grants, rechecks selection before
resource-version-bound Secret projection, reuses the existing rollout and
fingerprint probe, and retires previous in-memory credentials only after
consumption. Tokens travel through stdin rather than process arguments; receipts
contain safe digests, expiry and unavailable account/role metadata. Unconfirmed
delivery preserves uncertainty for recovery. Any unretired old lease after a
process loss remains bounded by GitHub expiry. A denied optional grant does not
disable healthy account grants or require a new provider at core startup.

### Backend and operator interface

OOS exposes authenticated, bounded, Console-only connection metadata. Its public
projection never returns a token or key. Requests resolve an exact account,
purpose, current grant and credential-binding reference. Denial, expiry, missing
account or binding mismatch never retries with another connection or an ambient
human credential. Readback verifies provider account ID/type and immutable repo ID.
Personal creation uses the provider's personal endpoint with explicit Private or
Public visibility; Internal remains organization-only. Original requests retain
their original target, approval and idempotency identity across default changes.

The Console automatically selects one eligible destination or shows **Create
under** for several. It derives account type and binding again server-side.
Loading, unavailable, retry and missing-setup states stay explicit. A destination
change requires another defaults review; incompatible visibility cannot submit.
The register uses dated provider evidence for Public/Private/Internal and Unknown
for absent evidence. A fresh selected History read may update visibility; no
register-wide provider scan or inferred public visibility is introduced.

New default workspace references include account and repository name. Existing
aliases remain stable. Qualified provider coordinates and immutable repository
IDs keep identical names in different accounts separate; native Registry metadata
exposes provenance without changing private record identity or storage authority.
Private source is not added to public Studio records or automatic model context.

### Contracts, deployment and packaging

Canonical Governance scopes and schemas allow personal and organization accounts.
WGCF readiness and OOS copies must pin the landed authority bytes; Platform's
custody-policy reference must match. Contract versions retain the existing
artifact shape; new scope is bound through current policy digest and approval.
Rollout checks retained request state before replacing authority. Old terminal

There is no new service, database, ART initiative, improvement candidate or

changes. Engineering configuration and this developer installation cannot close
