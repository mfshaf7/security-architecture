## Scope Delta

Platform's existing management-authenticated listener exposes bounded registered
workflow setup. It uses resolved caller/output contracts, actual schema digests
and admitted task IDs. The rendered runtime ConfigMap includes and imports the new helper dependency.
No private schema body, provider credential, account token
or model inference is returned or triggered. The source digest binds relevant
setup; unrelated provider selection does not invalidate an unchanged draft.

OOS adds caller/operator-bound setup read and prepared submit adapters. Strict
operator input cannot supply an operator identity, caller binding, output schema,
context digest or destination endpoint. Current setup version/environment are
checked before context admission. The configured CGG origin uses its established
generic text-admission API and runtime/network admission; it is not falsely
represented as a newly authenticated caller-specific projection adapter.
This is supporting context for a profile request, not permission to send future
restricted data to a model. The declared data classification remains a proposal.

OOS accepts only safe-redaction, raw-projection-denied admission metadata with a
real artifact ID and digest. It constructs the reference from CGG's existing
packet route on the configured origin. Raw paths/content are not returned to the
browser. Request state uses the unchanged native schema, create/submit service,
operator binding, revision controls and receipts. CGG retains its existing
private raw/artifact custody. Concurrent identical attempts can create more than
one CGG artifact, but the native original request and its history remain singular.
No globally exactly-once admission claim or new replay store is introduced.

The Console removes the wizard and uses a compact separate result. Normal
choices are workflow, name, purpose, reason, environment and data sensitivity,
plus optional rules. Technical setup remains an explicit integration-maintainer
path. Revision preserves existing supporting references unless explicitly edited.
Native requested-change resubmission is exposed rather than requiring CLI use.
Unknown outcomes retain original recovery; proven pre-create rejections preserve
editable intent. Caller/source setup is revalidated server-side. Preview samples
are isolated to explicit disconnected mode and cannot dispatch real effects.

### Same-batch history and outcome repairs

OOS extends its existing caller-owned list with optional bounded summaries. The
full view remains compatible; native request/review/fulfillment schema bytes
remain unchanged. Summary metadata excludes context, decision evidence, receipts
and event bodies. It is not mutation authority; selected records still pass the
current source envelope and native revision/receipt checks. Source paging uses
consistent cursor ordering. The private JSON state is still loaded once per
requested page; no new index, cache or storage boundary is claimed.

The Console reads profiles independently, loads25 summaries on demand and fetches
full evidence only for a selected request or explicit recorded-setup reuse.
History failures cannot clear valid profile source. Profile status reports only
its checked source and does not mark the independently lazy request API current. Dirty record/reference
changes use explicit discard; typed references do not change the active review.
Frozen uncertain commands retain exact read/retry recovery. A confirmed API
connection receipt is distinct from subsequent current-state/register read
failure. Keys remain outside recovery state and are never retried automatically.
No provider scope, identity, lifecycle action or runtime activation is added.
