## Trust boundary and review

The same App installations, grants, accounts, purposes, private selections, Vault
key custody and Secret authorities remain. No new identity/store/proxy/queue or
ART work is introduced. The reader account/token are one JSON bundle projected
from the validated existing Secret. Account, role, approval binding and immutable
repository checks stay in the existing provider clients. File paths are fixed
server configuration; browser input cannot select a path or credential source.

OOS reads bounded current files per operation. One mutation keeps one generation;
the next operation reads the renewed one. A configured file missing, malformed,
empty, oversized or expired fails closed without stale environment fallback.
Optional connection failure stays local and does not gate core Console or AI.
The existing connection projection excludes token values. Raw file exceptions
and credentials are not returned to browsers, argv or receipts.

Platform mounts optional Secret directories read-only without subPath. Current
expiry/version/digest observations move off PodTemplate onto Deployment metadata.
Routine GitHub renewal therefore cannot replace OOS. Source/configuration changes
and actual WGCF caller replacement retain required rollouts because those caller
credentials remain environment-backed. This bounded correction does not promise
survival of every intentional deployment or hardware interruption.

Five required projected tokens use one bounded 150-second readback wait before
old token revocation. The optional reader/connection projections also prove their
current fingerprints before retirement. Scope checks and existing renewal locks
remain. The existing refresh-credentials action exposes its existing force option
for explicit qualification, with all accepted-source/active-runtime guards intact.
